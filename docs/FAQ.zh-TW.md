# 常見問題與排錯

[首頁](../README.zh-TW.md) · [English](FAQ.en.md) · [使用手冊](USER_GUIDE.zh-TW.md)

## SmartCluster 自帶 AI 嗎？

不自帶模型訂閱。診斷示範不使用 AI；真實分析由目標電腦已安裝、登入且啟用的 provider 執行，消耗該帳號的額度。Codex／Claude CLI 與 App 接收器為不同通道；Gemini 的新增能力需支援的執行節點，不能只因安裝本包就視為可用。

## 只用對話就可以操作嗎？

支援本機 stdio MCP 的客戶端完成連接後，可以查節點、派工、追蹤與操作已支援的本機服務／邀請功能。建立與切換群組仍使用網頁介面。AI 只回答操作建議時，先檢查工具是否載入、是否允許呼叫，以及有沒有實際結果。

## 第一次執行跳出 SmartScreen「Windows 已保護您的電腦」？

此版未簽署，這是預期中的提示。請先用邀請人給的 SHA-256 核對 ZIP（`Get-FileHash`），相符才繼續；不相符就停止並向邀請人確認。公司管理的裝置請交由 IT 決定。不要關閉 SmartScreen 或防毒；若防毒隔離了檔案，把雜湊與檔名交給 IT 或邀請人處理，不要自行加入排除。

## 為什麼不能只複製 SmartCluster.exe？

程式需要同一層的 `_internal` 資料夾（Python 執行環境、函式庫與網頁資產）。請一律搬整個 `SmartCluster` 資料夾。

## 關掉那個黑色視窗，群組會停嗎？

雙擊 `SmartCluster.exe` 出現的視窗是「我的群組」管理頁的服務；關掉它，管理頁就不能用，但**已啟動的群組背景服務不會停**。要停止群組請在管理頁按「停止服務」。登入後自動啟動用的是無視窗的 `SmartCluster-background.exe`，不會出現這個視窗。

## 怎麼更新？會自動更新嗎？

執行檔版不會自動更新，Hub 也不會推送給它（主控台顯示「執行檔安裝：手動更新」）。步驟見[使用手冊第 9 節](USER_GUIDE.zh-TW.md#9-手動更新此版沒有自動更新)：暫停接單、停止服務與 AI App、備份 `.smartcluster-groups`、新版解壓到新資料夾、改名讓路徑不變、啟動確認。退回舊版前先還原備份。

## 查看其他群，會送錯工作嗎？

「查看」不改接單。MCP 綁定指定的本機 profile，不隨 UI 選取或接單群改變。同一 registry 一次一個接單群；這不是全機所有獨立安裝的共同鎖。每次派工仍應核對群組與目標。

## App 工作為什麼一直排隊？

先確認接收器已連接、來源和專案在授權範圍內，再確認 App 有收件活動。手動接收器要在原對話說「請收取 SmartCluster 工作」。支援部署中的 Gemini sidecar 可通知已開啟的原生 App，但需另外安裝與設定；本次執行檔不提供此安裝流程。Node 在線或工作提交成功不代表 App 已領件或完成。

## 加入代表把整台電腦開放嗎？

不會。群組配對、AI 登入、專案授權、檔案交付與 App 收件分開設定。群主不能因為你加入就擴大本機授權。mTLS 驗證的是裝置／節點，不能當作完整的人員角色管理。

## 資料會傳到哪裡？

派工內容及結果會由協作鏈路處理並依功能保存；AI 分析會將你提交的內容交給目標節點及所選 AI 服務。完整 App 歷史留在原電腦。只分享當次工作必要內容；回報問題時不要附上原始工作資料、邀請或憑證。

## 為什麼介紹 Gemini／CTE，但本機不能隔離開發？

介紹涵蓋整個 SmartCluster 協作流程；本試用包的角色是 Windows 管理／派工端與支援的本機節點功能。本次 frozen Node 不執行 `agent.develop`，也不提供 Gemini CLI 或 Gemini App MCP／sidecar 安裝。這些工作需要已配置、已驗收且授權的執行節點。選擇能執行該任務的目標，不能靠改顯示標籤或取消保護啟用能力。[完整矩陣](RELEASE_NOTES.zh-TW.md)

CTE-Codex 主程式不包含在本包。bridge 的完整開發驗收是既有 Primary 開發部署的成果；不支援再分工、Hub 覆寫模型或完整 token 用量。

## Gemini 模型設定會同步到桌面 App 嗎？

不會。Hub 管理的 CLI 模型與 Gemini 桌面 App 原生模型選擇器分開；各自設定並驗收。已設定標籤也不代表 App 收件服務正在運行。

## 常見故障

| 現象 | 處理 |
|---|---|
| 管理頁失效或要求登入 | 從 EXE 重新取得本機入口，不分享含登入資訊的 URL |
| 服務顯示可接單卻未執行 | 先啟動服務，再查健康狀態與診斷結果 |
| AI 查到不同群組 | 核對 MCP 的 profiles-dir 及 profile_id；不是 cluster_id |
| AI 說找不到 SmartCluster 工具 | 核對 MCP 設定中的 EXE 完整路徑與參數順序（`--profiles-dir … --profile … mcp`），然後**完全結束並重開** App |
| 加入逾時 | 核對版本、Hub 位址與實際埠、路由及允許的防火牆規則 |
| 邀請或憑證不符 | 向群主重新核對來源、時間及指紋，不跳過 TLS 驗證 |
| 加入過程中斷 | 優先接續現有加入紀錄；不要連續新增身分 |
| 切換一直等候 | 核對原群未結任務；完成後繼續，或取消切換 |
| 結果待核對 | 查實際產物與程序，保留紀錄，不自動重做副作用 |
| 找不到舊群 | 新 registry 不會自動匯入舊安裝；保留原資料 |
| 自動啟動沒有生效 | 搬動或換版資料夾後要重新開啟自動啟動；它記錄的是絕對路徑 |
| EXE 被系統攔截 | 候選版未簽署，核對來源及雜湊後交 IT 或邀請人，不關閉防護 |

## 可以直接商業部署嗎？

目前仍是試用版，產品授權、支援與服務承諾尚未公布；試用條款見[版本狀態](RELEASE_NOTES.zh-TW.md)。第三方 AI 和 VPN 方案各有自己的條款；請依用途核對，不要把試用或第三方免費方案視為商業使用許可。[WAN 指引](WAN.zh-TW.md)

## 執行檔封裝是否能保護原始碼？

不能保證。EXE 與 `_internal` 內含可讀取且與原始碼相同的 HTML／CSS／JavaScript 資產，以及全部產品 Python 位元組碼。PyInstaller 封裝不提供程式內容保密：網頁資產可以抽出，位元組碼可能被分析或反編譯。擁有者已決定在揭露此限制的前提下提供限邀請試用。

## 如何回報？

試用為限邀請，請直接向邀請人私下回報。提供版本、作業系統、單機／LAN／WAN、重現步驟、預期與實際結果、遮敏後的錯誤代碼。截圖先去除帳號、IP、路徑、任務內容及短效登入資料。沒有自動遮敏匯出功能。發現敏感問題時不要公開漏洞利用細節或秘密。
